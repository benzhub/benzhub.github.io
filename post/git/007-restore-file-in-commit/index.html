Git 還原誤刪檔案：保留既有提交歷史的做法

2024/02/17 2026/11/12
git

如果某個已追蹤檔案在後續提交被刪除，git restore --source=<仍含檔案的提交> -- <路徑> 可以從舊快照取回該檔案，保留既有提交歷史。先確認要取回的是哪個版本，並檢查工作目錄是否已有同名檔案或未提交修改。

用隔離倉庫重現誤刪與還原

以下範例只操作新資料夾，需要 Git 2.23 以上：

mkdir restore-demo && cd restore-demo
git init -b main
git config user.name Demo
git config user.email demo@example.invalid
printf 'keep this\n' > note.txt
git add note.txt && git commit -m 'Add note'
git rm note.txt && git commit -m 'Remove note'
git log --oneline -- note.txt
git restore --source=HEAD~1 -- note.txt
cat note.txt
git status --short

cat 應輸出 keep this；git status --short 應顯示 ?? note.txt，因為目前的 HEAD 已不追蹤這個檔案。若要讓還原成果進入下一個提交，再執行 git add note.txt 與 git commit -m 'Restore note'。這是新增一個提交，不會重寫先前歷史。

如何選正確的來源提交？

git log --all -- <路徑> 可找檔案的提交紀錄；git show <提交>:<路徑> 可在動手前檢查該快照內容。若只想還原上個提交的版本，可用 HEAD~1；檔案在該提交中不存在時，請往更早的提交找。

git restore --source=<提交> -- <路徑> 預設寫入工作目錄，不會移動 HEAD。舊寫法 git checkout <提交> -- <路徑> 同樣是取出指定檔案，不會因此進入 detached HEAD；單獨執行 git checkout <提交> 才是切換到該提交。若工作目錄已有同名修改，先備份或提交，再還原，避免覆蓋。

更多指令可對照 Git restore 文件與常用 Git 指令。
