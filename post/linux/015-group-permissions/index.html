Linux 群組權限管理教學：chmod、chown 與 group 設定

2024/01/18 2026/11/11
linux

Linux 檔案權限先看三組身分：擁有者、所屬群組、其他人。chmod 改這三組的讀寫執行權限；chown 改擁有者或群組；usermod 改使用者屬於哪些群組。要修「Permission denied」，先確認自己是哪個使用者、目標檔案歸誰，以及路徑上的目錄能否進入。

先讀懂 ls -l 的輸出

-rw-r----- 1 alice editors 42 Nov 11 09:00 report.txt

最前面的 - 代表一般檔案，後面三組 rw-、r--、--- 依序屬於擁有者、群組、其他人。這個例子中 alice 可讀寫，editors 群組成員可讀，其他人無權限。目錄的 x 表示能穿越或進入，r 表示能列出名稱；要讀某個檔案，路徑上每層目錄通常也需要 x。ACL、掛載選項與安全模組可能另有限制，因此 ls -l 不是全部答案。

id
ls -ld . ./shared ./shared/report.txt
namei -l ./shared/report.txt

id 看目前群組；namei -l 逐層列出路徑權限，在 Linux 排查目錄問題很有用。

在自己的暫存目錄安全練習 chmod 與 chgrp

以下只操作新建的測試檔案，不需 sudo，不碰系統檔：

exercise=$(mktemp -d)
printf 'draft\n' > "$exercise/note.txt"
ls -l "$exercise/note.txt"
chmod 640 "$exercise/note.txt"
ls -l "$exercise/note.txt"
chmod u+x "$exercise/note.txt"
ls -l "$exercise/note.txt"

640 的三位數是擁有者 6=4+2（讀、寫）、群組 4（讀）、其他人 0。u+x 則只替擁有者新增執行權限，不會把其他既有權限洗掉。一般純文字檔不需要 x，上例是為了看出符號模式的差別。練習結束可用 rm -r "$exercise" 刪除剛才建立的目錄，先確認變數仍指向自己的測試路徑。

在一般 Linux 檔案系統上，兩次 ls -l 的權限會依序變成 -rw-r-----（640）和 -rwxr-----（740）。這裡的執行位只改了檔案模式，並不保證這份文字檔是有效程式。若是目錄，740 代表群組只有讀取而沒有 x，通常無法穿越該目錄，因此不該把檔案的數字模式直接搬去套目錄。

chgrp editors file 會改檔案所屬群組，但一般使用者只能設成自己有權使用的群組；chown alice:editors file 改擁有者與群組，通常需要管理權限。不要看到權限錯誤就對整棵專案跑 sudo chown -R 或 chmod -R 777，那可能破壞共用檔的安全設定。參考 chmod 手冊 和 chown 手冊。

要讓新成員進入群組時

管理者先確認群組名稱與帳號，再執行：

getent group editors
id alice
sudo usermod -aG editors alice
id alice

-aG 表示把 editors 加入附加群組；單用 -G 可能取代原有附加群組，讓使用者失去既有權限。群組變更對現有登入工作階段不一定立即生效；請使用者重新登入再用 id 檢查。這些指令會改系統帳號，只應由有權管理該機器的人在確認帳號後執行，不適合在共用或正式主機上照抄示例名稱。詳見 usermod 手冊。

共用目錄的權限怎麼規劃

「群組可編輯」不只要檔案有 g+w，目錄也需要適當的 g+w 和 g+x；新檔所屬群組與預設權限還受 setgid、umask 或 ACL 影響。實作時先在測試目錄驗證，再移到正式路徑。若只是某個服務無法寫入，先找出服務實際的使用者與群組，再給最小必要權限。要定期檢查任務的執行身分，可接著看 Cron Job 教學。

常見的 755 目錄允許其他人穿越和列名，但只有擁有者可寫；770 目錄讓擁有者與群組都能讀、寫、穿越，其他人無權限。實際選哪一個取決於資料是否要公開，以及目錄父層是否可穿越。共用資料若要讓新檔繼承目錄群組，可評估目錄的 setgid 位元和預設 ACL；先在測試目錄建立檔案，確認新檔的群組與權限符合預期。

先在自己的暫存目錄測試 setgid，不需要建立系統群組：

exercise=$(mktemp -d)
mkdir "$exercise/shared"
chgrp "$(id -g)" "$exercise" "$exercise/shared"
chmod 2770 "$exercise" "$exercise/shared"
old_umask=$(umask)
umask 007
printf 'draft\n' > "$exercise/shared/note.txt"
stat -c '%a %g %n' "$exercise/shared" "$exercise/shared/note.txt"
umask "$old_umask"

2 是目錄的 setgid 位，讓新檔沿用目錄所屬群組；在一般 Linux 檔案系統上，目錄會顯示 2770，新檔通常是 660。umask 007 只影響目前 shell 及其子程序，範例最後會還原原設定；它不會替其他登入使用者永久設定。ACL 或特殊掛載也可能改變結果；若新檔仍不是預期的群組或權限，要用 getfacl 和 stat 核對。測試後可確認 $exercise 路徑，再刪除這個暫存目錄。

正式的多人共用目錄需要管理者建立群組（例如 sudo groupadd editors）、用前述 usermod -aG 加入成員，再把既有共用目錄的群組設為 editors，例如 sudo chgrp editors /srv/team-share 與 sudo chmod 2770 /srv/team-share。執行前要確認父目錄、既有檔案擁有者、備份與 ACL；修改目錄群組不會自動更改其中舊檔案的權限，也不能替代成員重新登入。
