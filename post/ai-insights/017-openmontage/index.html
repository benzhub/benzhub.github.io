一句話就能剪出影片？OpenMontage 把 Claude Code 變成製片團隊 | AI Insights

2026/11/11
ai-insights AI OpenMontage Claude Code Codex AI 影片 Agent Skills

「幫我做一支影片」最難的，通常不是產出那五秒畫面。 真正會吃掉週末的，是查資料、寫腳本、找素材、配音、加字幕，再把所有東西剪成一支能看的片。OpenMontage 想把這串工作交給你已經在用的 coding agent，讓你負責方向與審核，agent 負責把製作流程跑起來。

OpenMontage 是什麼？一個放在 repo 裡的製片流程

OpenMontage 是開源的 agent 影片製作專案。你把專案打開，用 Claude Code、Codex 或其他能讀檔、執行程式的 coding agent 描述影片需求，agent 就依照 repo 裡的流程文件、Skills 和工具製作影片。它的核心不是某個「一句 prompt 生整支片」的模型，而是一套把不同工作接起來的製作方法。

這個區別很實際。影片模型擅長生成片段，但一支 45 秒的教學影片需要的是完整節奏：哪個概念先講、畫面在哪裡切、旁白何時停、字幕會不會擋住重點。OpenMontage 把這些決定拆成階段，讓你在花錢生成素材之前先看到企劃和分鏡。

先釐清一件容易混淆的事：目前可自行安裝的是 GitHub 上的開源專案。官網另有 OpenMontage Studio 桌面產品，頁面標示為 Windows private alpha、採候補邀請。這篇介紹的是前者，別把 Studio 的介面當成 clone repo 後就能使用的功能。

它怎麼把一句需求變成影片？

官方列出的主流程是：

research → proposal → script → scene_plan → assets → edit → compose

在 research 階段，agent 蒐集資料和視覺參考；proposal 決定影片方向、工具與預估費用；script 和 scene_plan 把內容拆成可拍、可剪的段落。接著才取得素材、配音與音樂，最後用 Remotion、HyperFrames 或 FFmpeg 合成影片。官方 README 把這套設計稱為 agent-first：coding agent 是流程的指揮者，Python 工具負責執行與保存狀態，YAML 和 Markdown 則寫著每個階段該怎麼做。

它也有幾個讓長任務比較可控的機制。企劃、腳本、分鏡和素材等創意關卡會停下來等你確認；每次選擇 provider 的理由與花費會寫進紀錄；Backlot 看板 則能顯示目前跑到哪一步。影片輸出後，專案還會檢查檔案資訊、抽樣畫格、音量與字幕。不過「有自動檢查」仍不等於「成片保證好看」，最後那次完整觀看不能省。

我覺得它最有意思的地方，是素材不一定要靠付費影片模型生成。你可以用開放影像素材剪一支紀錄片風格的片，也可以用靜態圖片、動態字卡與程式化動畫做技術解說。對想拍產品 demo 的開發者，官方還有 screen demo 流程；對已經有直播或長片的人，則有切短片的 clip factory。不同任務不必硬套同一個「AI 生成影片」模板。

先用零 API key 試，再決定要不要付費

官方的快速開始說明列出 Python 3.10 以上、FFmpeg 和相容的 Node.js 版本等前置需求。Node 的最低修補版會更新，安裝前請看 README 的目前要求。準備好後：

git clone https://github.com/OpenMontageInc/OpenMontage.git
cd OpenMontage
make setup
make demo

make demo 是官方提供的零 key 示範。想自己製作，就在這個資料夾開啟 Claude Code 或 Codex，給它一個可驗收的 brief。例如：

做一支 30 秒、9:16 的 React Server Components 入門短片。
觀眾是熟悉 React、第一次接觸 RSC 的前端工程師。
先用字卡與簡單圖解，不使用付費影片生成服務。
先提出腳本、分鏡、素材來源與費用估算，等我確認後再製作。
輸出 MP4；如果無法可靠產生繁體中文配音，就先做無配音版本。

這段 brief 把觀眾、時長、畫面風格、成本與語言限制先講清楚，比「幫我做一支很酷的 AI 影片」更容易審。繁中配音和字幕仍要自己檢查，尤其是技術名詞的發音與斷句。

付費 provider 接上前，先看預算設定。 目前 repo 的 config.yaml 預設 budget.mode: warn、總額 10.00 美元。warn 只記錄超支警告；如果你的需求是硬性停止，應改成 cap，再依自己的預算調整 total_usd。單筆超過預設 0.50 美元會要求核准，但這也不該取代你檢查雲端服務實際帳單。

什麼情況值得用？什麼情況直接剪比較快？

如果你每週都要做技術解說、產品更新或長片切短片，OpenMontage 最有價值的可能是可重複的工作流程：資料、腳本、素材、成本和成片都留在同一個專案裡。你可以修改 Markdown 規則或 React 動畫元件，慢慢長出自己的影片模板。

如果你只想把一段現成錄影剪掉前後空白、加兩張字卡，直接用熟悉的剪輯軟體或 FFmpeg 可能更快。OpenMontage 要安裝 Python、Node 和影片工具，也要花時間審核多個階段。它省的是重複規劃與組裝一整支影片的工，不是把創作判斷從你手上拿走。

成本也別只看「零 API key」。本機路線可以用 Piper TTS、開放素材與 Remotion／HyperFrames／FFmpeg 輸出，但會消耗你的電腦資源和 agent 使用額度。接上影片生成、商用配音或付費音樂後，費用與各服務條款又是另一回事。專案本身採 AGPL-3.0；要把修改後的系統做成商業服務，或在團隊裡使用 Remotion，請先核對相關授權條款，別只憑 repo 裡一句「開源」就下決定。

值得試，但先做一支小片驗證

我會從零 key 的 30 秒技術解說開始：先跑 make demo 確認環境，再讓 agent 只做企劃與分鏡，確認畫面節奏後才進入素材和輸出。成片要親自看過，檢查字幕、黑畫面、配音、素材授權與事實是否正確。

OpenMontage 的方向很有吸引力：把影片從「碰運氣生成一段 clip」變成可以追蹤、審核、重跑的製作流程。但這篇是根據官方文件與研究筆記整理，不是我親自跑完一支片的實測報告。如果你的目標是穩定產出，第一支小片的實際耗時、花費與觀感，會比星數和展示影片更有說服力。
