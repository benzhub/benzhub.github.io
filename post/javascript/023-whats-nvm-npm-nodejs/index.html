NVM 是什麼？NVM vs NPM vs Node.js 差異完整解析

2024/01/01 2026/11/11
javascript Nodejs npm nvm

node 執行 JavaScript，npm 管理專案套件，nvm 管理你在 shell 裡使用哪個 Node.js 版本。三者不是互相替代的產品：同一台電腦可以有多個 Node.js 版本，每個版本通常配有相應的 npm；進入不同專案時用 nvm 切換，再用 npm 安裝該專案依賴。

一眼看懂三者分工

名稱主要工作常用指令
Node.js執行 JavaScript 程式node --version、node app.js
npm CLI依 package.json 與 lockfile 安裝、執行專案套件npm ci、npm run build
nvm（nvm-sh）安裝、切換 shell 中的 Node.js 版本nvm install、nvm use

npm 也可能指線上的套件 registry，這裡主要說的是命令列工具。nvm 不是 npm 套件，不應用 npm install nvm 來代替安裝版本管理工具。Node.js 的支援狀態會變，請查 官方 release 清單，不要把舊文章指定的主版本當成永遠最新的 LTS。

進入既有專案時怎麼做

先看專案是否有 .nvmrc、package.json 的 engines 欄位和 lockfile。.nvmrc 若含有例如 24，代表這個專案希望使用對應的 Node.js 主版本；它不會自動安裝專案套件。

cat .nvmrc
nvm install
nvm use
node --version
npm --version
npm ci
npm run build

nvm install 和 nvm use 在有 .nvmrc 的目錄會讀取它；沒安裝指定版本時，nvm use 會失敗，先執行 nvm install。npm ci 需要相容的 lockfile，會依 lockfile 做乾淨安裝；沒有 lockfile 或想更新依賴時，才依專案規範使用 npm install。詳細行為參考 nvm 的 .nvmrc 文件 與 npm ci 文件。

不要把 .nvmrc 和 package-lock.json 當成同一種鎖定。前者選 Node.js 版本，後者記錄 npm 依賴樹。npm ci 若發現 package.json 與 lockfile 不一致會失敗，不會默默替你重寫 lockfile；這正是 CI 需要的可重現性。如果套件要求更高的 Node.js 版本，應檢查 engines 與安裝錯誤，不能只把 npm 更新到最新版就期待問題消失。

若是新專案，先確認目標 Node.js 的支援版本，再把團隊決定的版本寫進 .nvmrc。不要只寫 node 或 lts/* 就以為版本完全固定，這兩者會隨時間指向較新的版本；需要可重現環境時指定明確版本並配合 CI。

nvm 指令找不到時檢查什麼

macOS/Linux 使用的 nvm-sh/nvm 通常是 shell function，不是一個一般的執行檔。新開終端機後，先用 command -v nvm，再看 shell 啟動檔是否依 官方安裝說明 載入 nvm。若 node --version 仍不是預期值，用 which node（或 command -v node）確認 PATH 上是否有另一套安裝覆蓋。安裝步驟與 shell 差異請看 macOS/Linux 安裝 nvm；Windows 的 nvm-windows 是不同專案，指令和安裝方法應查 Windows 安裝文章 並核對其官方文件。

症狀先檢查
nvm: command not foundshell 設定檔有沒有載入 nvm？是否重開終端機？
nvm use 找不到版本.nvmrc 寫的是哪個版本？先執行 nvm install。
node --version 沒變command -v node 指向哪裡？目前 shell 是否載入了另一套版本管理器？
npm ci 失敗lockfile 是否存在、是否和 package.json 一致、Node.js 版本是否符合專案要求？

把這些輸出連同作業系統、shell、node --version 和 npm --version 一起記錄，比只截「安裝失敗」訊息更容易定位問題。

nvm、fnm 與近似文章的界線

這篇處理概念與專案工作流程。如果你想了解 nvm 的更完整用法，接著看 nvm 專文；如果正在比較替代版本管理器，再看 fnm 指令教學。切換工具前要確認團隊的 .nvmrc、CI 與 shell 設定是否一致，而不是單憑未測量的速度宣稱選擇。
